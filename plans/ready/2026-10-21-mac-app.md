# Nylon for Mac

**Date**: 2026-10-21
**Status**: Ready

## Problem

Nylon runs on the web, iPhone, iPad and in Gmail, but not natively on the
Mac. The iPad already has the wide board (sidebar, three time columns, a
fourth for one of your lists, an inspector and a keyboard map) that the
cohesive redesign (`plans/done/2026-10-18-cohesive-redesign.md`) specified for
wide screens. A Mac app is mostly that board in a Mac window, plus the places
a Mac user expects to reach a todo app from without opening it: the menu bar,
a global hotkey, desktop widgets, the Share menu and the Dock.

## Solution

A **native SwiftUI macOS destination of the existing app target**, not Mac
Catalyst and not a fork. The shared code (models, SwiftData store, sync,
WebSocket, typed-date parser, `TodoActions`, the wide board) compiles for
both platforms; the handful of UIKit touch points sit behind small platform
shims, and Mac-only surfaces live in files wrapped in `#if os(macOS)`.

Decisions (from the owner, 2026-10-21):

- **Approach:** native SwiftUI, macOS added as a destination of the existing
  targets. Not Catalyst.
- **Distribution:** Mac App Store via TestFlight, **Universal Purchase** — the
  same bundle IDs as iOS (`com.superhighfives.Nylon-Impossible` and its two
  extensions).
- **Minimum macOS:** 14 (Sonoma) — SwiftData, `@Observable`, interactive
  widgets and `MenuBarExtra` all exist there. Anything newer (Liquid Glass,
  `pointerStyle`) is availability-gated with a fallback.
- **v1 extras, all four:** menu bar quick-add with a global hotkey, desktop
  widgets, a Share extension, a Dock badge.

### Targets

No new targets. Each existing target gains `macosx` in
`SUPPORTED_PLATFORMS`, so one target builds an iOS and a macOS product:

| Target | iOS product | macOS product | Notes |
| --- | --- | --- | --- |
| `Nylon Impossible` | `.app` | `.app` | macOS entitlements file via `CODE_SIGN_ENTITLEMENTS[sdk=macosx*]` |
| `Nylon Widget` | `.appex` (WidgetKit) | `.appex` (WidgetKit) | Same extension point; the control widget is iOS-only |
| `Nylon Share` | `.appex` (`com.apple.share-services`) | `.appex` (same point) | `NSViewController` principal class on macOS |
| `Nylon ImpossibleTests` | `.xctest` | `.xctest` | Hosted in the macOS app |
| `Nylon ImpossibleUITests` | `.xctest` | — | Stays iOS-only for now |

WidgetKit and Share extensions are multiplatform extension points, so the
same targets can carry both — **no new target, and no new App ID.** What *is*
new is a **macOS provisioning profile for each of the three signed targets**:
an App ID enabled for macOS still needs a Mac App Store profile per bundle ID.

### Entitlements (macOS)

Separate `*-macOS.entitlements` files, picked with
`CODE_SIGN_ENTITLEMENTS[sdk=macosx*]`, so the iOS files are untouched:

- **App Sandbox** (`com.apple.security.app-sandbox`) — required on the Mac App
  Store, for the app and for every extension.
- **Outgoing network** (`com.apple.security.network.client`) — the API, the
  WebSocket, favicon and link fetches. The widget needs it for
  `CompleteTodoIntent`'s immediate upload. No user-selected-file access: the
  app never opens or saves documents.
- **App Groups.** macOS has always accepted *Team ID–prefixed* group IDs
  without registration; iOS-style `group.` IDs are only honoured on macOS 15+
  when a provisioning profile authorises them, and on 14 the rule is murkier.
  The Mac targets therefore use **`TGHU37N6EX.com.superhighfives.Nylon-Impossible`**,
  the documented macOS form. The store isn't shared across devices anyway
  (each Mac and phone has its own local cache), so a different string on Mac
  costs nothing and removes a provisioning dependency. One constant,
  `AppGroup.identifier`, replaces the five hard-coded copies.
- **Keychain Sharing** — `$(AppIdentifierPrefix)com.superhighfives.Nylon-Impossible.shared`,
  as on iOS. `KeychainHelper` sets `kSecUseDataProtectionKeychain` on macOS so
  the access group applies (the legacy file keychain ignores it).
- **Associated Domains** (`webcredentials:` for Clerk) — kept on the app.
- **Not on macOS:** `com.apple.developer.siri` (App Intents don't need it on
  Mac), `BGTaskScheduler` (a Mac app keeps running; the menu bar extra keeps
  it alive).

### Mac shell

- `WindowGroup` with the wide board inside a `NavigationSplitView`: sidebar
  (the iPad sidebar), the board (three columns plus your list's column), and
  the detail/Done/Settings inspector. Native toolbar with the sidebar toggle,
  New Todo and an inspector toggle; the window title is the focused list;
  minimum size 720×480, default 1280×800. A narrow window collapses the
  sidebar and the columns scroll sideways at their minimum width — the phone
  pager is not used on Mac.
- **Menus** (`.commands`): File (New Todo ⌘N, New List ⇧⌘N), Edit (Undo ⌘Z
  reaches the toast's Undo through the window's `UndoManager`), View (Today
  ⌘1, This Week ⌘2, Someday ⌘3, Show Done ⇧⌘D, Toggle Sidebar), Todo (Mark
  Done, Open, Move to ▸, Pin, Due…, Delete, Next/Previous), Window, Help.
  Command metadata (titles, key equivalents, routing) lives in one
  `BoardMenuCommand` table that tests can read.
- **Single keys** from the iPad map (`j`/`k`, `h`/`l`, `x`, `1`/`2`/`3`, `p`,
  `d`, Delete, `n`, Return) work while focus isn't in a text field, exactly
  as on iPad (`BoardKey`).
- **Settings scene** (⌘,): General (appearance, timezone automatic or by
  hand, menu bar icon, global hotkey, Dock badge) and Account (who you are,
  Sign Out, Delete Account).
- **Mac details:** hover tints (existing), right-click context menus
  (existing `TodoContextMenu`), drag between columns (existing), **drag in
  from other apps** — text or URLs dropped on a column become todos there, a
  todo per line — pointing-hand cursors on clickable chrome, focus rings, and
  ⌘Z for the Undo toast.
- **Type and colour** from `Theme`, which the token generator now emits for
  both platforms (`NSColor` dynamic provider with the Increase Contrast
  variants; `NSFont` for Archivo). Archivo is registered with
  `ATSApplicationFontsPath` in the app and the share extension.

### Menu bar quick-add

- `MenuBarExtra` (window style) with the composer (list chips, "Due Fri ×"
  from `TodoDateParser`, Return adds), the Today count, and the next five
  Today todos with tick-to-done (`TodoCompletionService` via `TodoActions`).
- **Global hotkey**, default ⌃⌥Space, configurable in Settings, opens the
  same quick-add in a floating panel from anywhere. Implemented directly on
  Carbon's `RegisterEventHotKey` (`GlobalHotKey.swift`, ~150 lines): it's
  sandbox-safe and needs no Accessibility or Input Monitoring permission,
  which is what makes it the API `KeyboardShortcuts` and every Mac App Store
  launcher use. Writing the thin wrapper ourselves avoids a third-party
  package and its resources for one hotkey, keeps `Package.resolved` (and so
  the iOS build) unchanged, and keeps the key-code/modifier translation in a
  pure, unit-tested type.
- A Settings toggle shows or hides the menu bar icon
  (`MenuBarExtra(isInserted:)`).

### Widgets

The same `TodayProvider` and `TodayWidgetView`, plus a `.systemLarge` layout,
on the desktop and in Notification Center. Families are per platform: small,
medium and large on macOS; the existing small, medium and Lock Screen
families on iOS are unchanged. Tick-to-done is the existing
`CompleteTodoIntent`; "+" is the existing `OpenComposerIntent`, which on Mac
brings the window forward with the Today composer focused. The Control Center
control stays iOS-only.

### Share extension

"Share → Nylon" from Safari and any app that shares text or a URL. The
extension's content handling (URL vs text, the sharing app's title) moves
out of the UIKit controller into a shared `ShareExtensionLoader`; the iOS
`UIViewController` and the new macOS `NSViewController` are thin hosts around
the same `ShareSheetView` and `ShareCapture`.

### Dock badge

`DockBadge` shows the open count of the Today digest (`TodayDigest` — the
Today list plus anything due before midnight, the same set the widget and the
menu bar show) on the Dock icon. Recomputed when the store saves (which covers
sync, the menu bar, the widget's intent and every edit), at midnight, and on
activation. Off switch in Settings.

### Sync and auth

The same `APIService`, `SyncService` and `WebSocketService`. On Mac the
socket stays connected while the app runs (the menu bar and badge need live
data even with no window), reconnecting on wake; it doesn't disconnect when
the app loses focus. `ClerkKitUI` is compiled out on macOS (every file is
`#if os(iOS)`), so Mac sign-in is a small native **email code** flow on
`ClerkKit` (`signInWithEmailCode` → `verifyCode`, falling back to sign-up for a
new address). Tokens are written to the shared Keychain item as on iOS.

### DEBUG screenshot routes

`-NylonScreen board|column|inspector|detail|done|settings|menu|widgets|share|sharetext|signin|…`
work on macOS. Mac additions: `menubar` (the quick-add view), `macsettings`
(the Settings window), and `-NylonSnapshot <path>` writes the window's
rendering to a PNG, so screenshots don't depend on Screen Recording
permission.

### CI and release

- `ios-test.yml` gains a `macOS` matrix entry: build and run the unit tests
  with `-destination 'platform=macOS'`, unsigned (`CODE_SIGNING_ALLOWED=NO`).
- Fastlane gains `platform :mac` with `beta` (TestFlight) and `release`
  lanes: archive for `generic/platform=macOS`, export a `.pkg` with
  `app-store-connect` and manual Mac profiles, upload with `app_platform:
  "osx"`.
- `ios-deploy.yml` and `ios-release.yml` gain a separate `deploy-mac` job,
  skipped unless the repository variable `ENABLE_MAC_RELEASE` is `true`. The
  iOS jobs are not changed.

## Implementation

### Key considerations

- **Expand, don't fork.** A view gets `#if os(macOS)` only where the API
  doesn't exist on the other platform; behaviour stays in shared types.
- **iOS must not change.** Same bundle IDs, same entitlements files, same
  families, same release jobs. Verified by building and testing iOS on iPhone
  and iPad after every step.
- **Extensions compile a subset.** A new shared file has to be added to the
  extension's `membershipExceptions` as well as written (see the iOS README).

## Apple Developer and App Store Connect steps (owner)

1. Developer portal → Identifiers → `com.superhighfives.Nylon-Impossible`:
   confirm the App ID can be used for macOS (an explicit App ID is
   multiplatform; check App Groups, Keychain Sharing and Associated Domains
   are enabled). Repeat for `.Nylon-Share` and `.Nylon-Widget`.
2. Profiles → three **Mac App Store** distribution profiles (macOS platform):
   "Nylon Impossible Mac AppStore", "Nylon Share Mac AppStore", "Nylon Widget
   Mac AppStore".
3. Certificates → a **Mac Installer Distribution** certificate (the
   existing Apple Distribution certificate signs the app itself).
4. App Store Connect → the Nylon app → add the **macOS** platform (same
   record, so Universal Purchase), category Productivity, Mac screenshots,
   and a macOS TestFlight group.
5. GitHub → secrets `MAC_APP_PROFILE_BASE64`,
   `MAC_SHARE_EXTENSION_PROFILE_BASE64`, `MAC_WIDGET_EXTENSION_PROFILE_BASE64`,
   `MAC_INSTALLER_CERTIFICATE_BASE64`, `MAC_INSTALLER_CERTIFICATE_PASSWORD`;
   then the repository variable `ENABLE_MAC_RELEASE=true`.

## Risks

- **Sandbox.** Any file, Apple Events or launch-at-login need would add
  entitlements; none is planned.
- **App Group naming.** The Team-prefixed ID is the safe macOS form; if
  App Review or a future macOS insists on the iOS-style ID, it's a
  one-constant change plus adding the group to the Mac profiles.
- **Global hotkey.** `RegisterEventHotKey` is allowed in the sandbox and
  needs no permission prompt, but fails silently if another app owns the
  combination; Settings reports that.
- **Clerk on macOS.** Only `ClerkKit` supports macOS; the email-code flow is
  ours to maintain, and social sign-in isn't offered on Mac in v1.
- **App Review.** Menu bar apps must still have a main window and a way to
  quit; Nylon keeps both. Universal Purchase requires the same bundle ID,
  which this keeps.

## Acceptance criteria

- [ ] `xcodebuild build` succeeds for macOS and for iOS.
- [ ] Unit tests pass on macOS, iPhone and iPad.
- [ ] SwiftLint reports no new violations.
- [ ] The Mac app opens to the board via `-NylonScreen board`, light and
      dark, with the menus, Settings window, menu bar extra, a context menu,
      the widget gallery and the share sheet screenshotted.
- [ ] Single-key shortcuts work with focus outside text; ⌘Z undoes a done.
- [ ] Text or a URL dropped on a column from another app becomes a todo.
- [ ] The Dock badge shows the Today count and follows edits and syncs.
- [ ] The global hotkey opens quick-add from another app.
- [ ] CI runs the macOS unit tests; the Mac release job exists, is disabled,
      and the iOS release path is unchanged.
