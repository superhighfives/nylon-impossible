## Overview

Unchecking a completed todo used to send it back to its old fractional-index
position, so it jumped away from where the user tapped. Now an unchecked todo
gets a fresh position after the last incomplete one and lands at the bottom
of the active list. The fix went into iOS and web together in #29
(2026-03-09), a week and a half after the plan was written; the same commit
moved iOS tests into their own `ios-tests.yml` workflow.

## Architecture

On iOS, `toggleTodo` in `TodoViewModel` takes the full `allTodos` list. When
unchecking, it sorts the incomplete todos by position and assigns
`generateKeyBetween(last, nil)`. Completing a todo leaves its position alone,
since completed todos sort by completion time anyway. `ContentView` passes
`todos` at the call site.

The plan only describes iOS, but the web half shipped in the same commit:
`handleToggle` in `TodoList.tsx` sent `completed: false` together with a new
position after the last displayed incomplete todo.

On iOS the rule survives: it now lives in `TodoCompletionService.toggle`,
shared with the widget's toggle intent, and only looks at top-level siblings
in the same list. Web changed. `TodoList.tsx` was removed in the 2026-10
redesign (#401), and restoring a todo from Done history now puts it at the
*top* of its list (`topPosition` in `phone/useTodoActions.ts`), not the
bottom. It still gets a fresh position, so the original snap-back bug stays
fixed, but the two platforms no longer agree on where the todo lands.

## Problem

When a user unchecked a todo, it would snap back to its original position (based on its fractional index), creating a confusing UX where the item would jump away from where the user tapped.

## What Was Done

- Updated `toggleTodo(_ todo:, allTodos:)` signature in `TodoViewModel`
- When unchecking, filters incomplete todos, sorts by position, and assigns a new position after the last one via `generateKeyBetween`
- Updated call site in `ContentView` to pass `todos`
- Added `toggleTodoUncheckedMovesToEnd` test
- Fixed CI: simulator discovery for `macos-26` runner (iOS runtimes not pre-installed)
- Fixed CI: invalid fractional index key `"b0"` in test (correct next key after `"a0"` is `"a1"`)
- Fixed CI: added `@MainActor` to `toggleTodo` tests that mutate `@Model` properties off the main thread
